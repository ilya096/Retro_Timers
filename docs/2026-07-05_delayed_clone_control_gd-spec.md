## 1. Саммари Фичи

- Что это: после запуска отмотки текущая итерация скрывается, а новая управляемая итерация появляется не мгновенно, а после расчетной задержки; до появления игрок видит ghost/preview точки spawn и радиальный progress-индикатор.
- Для кого: для игроков, строящих puzzle-решение через несколько временных итераций.
- Какую проблему решает: предотвращает хаос и стартовую блокировку прошлых клонов новой итерацией, сохраняя читаемый порядок таймлайна.
- Ожидаемый эффект: игрок воспринимает задержку как часть правил времени, а не как лаг управления.

## 2. Бизнес-Контекст

- Почему фича появилась: без задержки новая итерация может физически мешать прошлым клонам на старте и разрушать запись.
- Почему сейчас: фича нужна для будущего tutorial/onboarding, где игрок должен понять причинность "прошлые клоны освобождают стартовую зону -> я появляюсь здесь".
- Какие альтернативы рассматривались:
  - мгновенно создавать игрока после отмотки;
  - создавать игрока сразу, но без управления;
  - откладывать появление до освобождения spawn-точки.
- Почему выбранный подход лучше альтернатив: фиксированное расписание сохраняет понятную формулу таймлайна, а ghost/preview объясняет ожидание без текстовой перегрузки.

## 3. Цели

- Главная цель: задержка предотвращает стартовую блокировку прошлых клонов без ощущения лага управления.
- Вторичные цели:
  - показать игроку точку будущего появления;
  - связать задержку с таймлайном, а не с потерей ввода;
  - оставить геймдизайнеру контроль тайминга на уровне;
  - сохранить цену отмотки через общий таймер.
- Что НЕ является целью:
  - динамически искать безопасную spawn-позицию;
  - гарантированно устранять все физические конфликты на spawn;
  - показывать обучающий текст поверх каждого появления.

## 4. Метрики Успеха

- Основная метрика: задержка и ghost/countdown читаются как часть таймлайна, а не как лаг управления.
- Дополнительные:
  - игрок понимает, где появится новая итерация;
  - игрок видит progress до появления без чтения HUD;
  - прошлые клоны успевают выполнить стартовые действия до появления новой итерации.
- Guardrail-метрики:
  - ghost/progress не перегружают экран;
  - spawn по расписанию не ломает базовый тестовый сценарий;
  - почти нулевая задержка не создает лишний UI-шум.

## 5. Позиционирование В Системе Проекта

- Место в core loop: включается после каждой отмотки, когда создается новая управляемая итерация.
- Этап игрока: early; должна быть понятна уже в onboarding-уровнях.
- Какие системы использует:
  - `time_rewind`;
  - `clone_recording_and_playback`;
  - `clone_readability`;
  - таймер уровня.
- Какие системы может затронуть/сломать:
  - стартовые коллизии клонов;
  - восприятие контроля;
  - баланс числа полезных итераций;
  - tutorial-подачу таймлайна.

## 6. Scope

### In Scope

- Линейная формула задержки:

```text
player_control_delay = clone_spawn_delay_seconds * completed_rewind_count
```

- `clone_spawn_delay_seconds` читается из gameplay/balance config.
- У уровня есть override `clone_spawn_delay_seconds` поверх проектного дефолта.
- До появления новой итерации показывается ghost/preview в точке spawn; preview не виден во время обычного управления до события rewind.
- Вокруг ghost/preview показывается радиальный progress-индикатор без текста.
- Progress показывает оставшееся время относительно полного времени до получения контроля.
- Если полное время до получения контроля меньше `0.25` секунды, countdown/preview не показываются; вместо этого используется короткий spawn flash.
- При появлении новой итерации используется короткий звук или визуальный pulse без текста.
- Если во время задержки уровень проигран, ghost/countdown скрываются мгновенно и показывается fail-state.

### Out Of Scope

- Динамическое откладывание spawn до освобождения точки.
- Поиск альтернативной spawn-точки.
- Текстовое обучение внутри обычного gameplay HUD.
- Мобильный UX задержки.

### Future

- Theme/preset-управление видом preview.
- Более сильный VFX переход ghost -> active player.
- Tutorial-уровни, где задержка объясняется через безопасную стартовую зону.

## 7. Use Cases / УФЧ

### 7.1 Обычная Отмотка

- Триггер: игрок запускает ручную или автоматическую отмотку.
- Действия игрока: наблюдает playback прошлых клонов.
- Реакция системы: показывает ghost/preview будущего spawn и progress до появления.
- Результат: игрок понимает, где и когда вернется контроль.

### 7.2 Почти Нулевая Задержка

- Триггер: рассчитанное полное время до получения контроля меньше `0.25` секунды.
- Реакция системы: не показывает полноценный ghost/countdown, а дает короткий flash в точке spawn.
- Результат: игрок не получает лишний UI для почти мгновенного появления.

### 7.3 Spawn В Занятой Точке

- Триггер: в момент появления прошлый клон находится в spawn-точке.
- Реакция системы: новая итерация появляется по расписанию; физика решает конфликт.
- Результат: формула задержки остается честной и предсказуемой.

### 7.4 Fail-State Во Время Задержки

- Триггер: playback-клон погибает до появления новой итерации.
- Реакция системы: ghost/countdown сразу скрываются, spawn отменяется, показывается fail-state.
- Результат: игрок не ждет появления итерации в уже завершенном уровне.

## 8. Сущности

- Сущность: delayed spawn preview
  - Назначение: показывает точку будущего появления новой управляемой итерации.
  - Поля/параметры: spawn position, remaining delay, total delay, visible flag.
  - Состояния: hidden, preview, spawn flash, cancelled.
  - Связи: зависит от `time_rewind`, player spawn и статуса уровня.

- Сущность: spawn progress indicator
  - Назначение: показывает прогресс задержки без текста.
  - Поля/параметры: normalized remaining delay.
  - Состояния: visible, hidden.
  - Связи: является частью delayed spawn preview.

## 9. Логика Работы

- Базовая формула остается линейной.
- Проектный дефолт `clone_spawn_delay_seconds` может быть переопределен уровнем.
- `player_control_delay` важнее полной защиты от всех физических конфликтов; spawn не откладывается из-за занятой точки.
- Если `total_spawn_preview_delay < 0.25`, система считает задержку почти нулевой и не показывает полноценный countdown.
- Progress-индикатор показывает оставшееся время относительно полного времени до получения контроля.
- При fail-state во время задержки preview скрывается сразу.

## 10. UI/UX

- Ghost/preview: силуэт игрока в точке будущего появления.
- Индикатор: небольшой радиальный progress без текста, расположенный над ghost.
- Максимальный диаметр индикатора: не больше ширины персонажа.
- Countdown-числа: только debug, не player-facing MVP.
- Spawn feedback: короткий звук или визуальный pulse без текста.
- Основной HUD не дублирует countdown.

## 11. Параметризация / Конфиги

- Параметр: `clone_spawn_delay_seconds`
  - Тип: float
  - Дефолт: `3`
  - Override: project default + level override
  - Кто меняет: геймдизайнер
  - Риск неверной настройки: слишком короткая задержка возвращает стартовый хаос, слишком длинная ощущается как потеря контроля.

- Параметр: `delayed_spawn_preview_threshold_seconds`
  - Тип: float
  - Дефолт: `0.25`
  - Кто меняет: UX / геймдизайнер
  - Риск неверной настройки: высокий порог скрывает полезный preview, низкий порог показывает UI на почти мгновенных spawn.

- Параметр: `delayed_spawn_radial_radius`
  - Тип: float
  - Дефолт: `0.32`
  - Ограничение: runtime clamp не больше половины ширины персонажа.
  - Кто меняет: UX / геймдизайнер
  - Риск неверной настройки: слишком большой индикатор конкурирует с ghost и клонами.

- Параметр: `delayed_spawn_radial_gap_above_ghost`
  - Тип: float
  - Дефолт: `0.12`
  - Кто меняет: UX / геймдизайнер
  - Риск неверной настройки: слишком маленький gap визуально слипает индикатор с ghost.

## 12. Формулы, Баланс-Переменные И Локализация

### 12.1 Формулы

```text
player_control_delay = clone_spawn_delay_seconds * completed_rewind_count
```

```text
total_spawn_preview_delay = rewind_transition_seconds + player_control_delay
```

```text
spawn_progress_normalized = 1 - remaining_until_control / total_spawn_preview_delay
```

### 12.2 Переменные Баланса

- `clone_spawn_delay_seconds`
- `delayed_spawn_preview_threshold_seconds`
- `delayed_spawn_radial_radius`
- `delayed_spawn_radial_gap_above_ghost`

### 12.3 Ключи Локализации

- Player-facing текстов для MVP нет.
- Debug namespace: `feature.delayed_clone_control`
  - `spawn_delay_debug`
  - `spawn_preview_debug`

## 13. Контекстные Системы

- Затронутая система: `tutorial_onboarding`
  - Что меняется: tutorial должен показать, что задержка дает прошлым клонам место выполнить стартовые действия.
  - Риск интеграции: игрок может воспринять задержку как потерю контроля.

- Затронутая система: `clone_readability`
  - Что меняется: preview использует визуальный язык игрока/клонов, но не должен путаться с активной итерацией.
  - Риск интеграции: ghost может конкурировать с активным игроком и playback-клонами.

## 14. Аналитика И Трекинг

- Event map:
  - `delayed_spawn_preview_shown`
  - `delayed_spawn_completed`
  - `delayed_spawn_cancelled`
- Обязательные параметры:
  - `level_id`
  - `completed_rewind_count`
  - `player_control_delay`
  - `clone_spawn_delay_seconds`
  - `cancel_reason`

## 15. Edge Cases И Исключения

- Если уровень проигран во время задержки, preview скрывается и новая итерация не появляется.
- Если spawn-точка занята, итерация появляется по расписанию.
- Если задержка почти нулевая, показывается только короткий flash.
- Если `clone_spawn_delay_seconds = 0`, новая итерация появляется сразу.

## 16. Риски И Митигации

- UX-риск: игрок может воспринять задержку как лаг управления.
  - Митигация: ghost/preview и progress в мире, привязанные к spawn-точке.
- Дизайн-риск: fixed schedule может иногда создавать spawn-конфликты.
  - Митигация: такие случаи считаются задачей левел-дизайна и проверяются в QA.
- Визуальный риск: preview может перегрузить экран.
  - Митигация: без текста в player-facing UI, числа только в debug.

## 17. Acceptance Criteria / QA

- Новая итерация появляется по формуле задержки.
- До появления виден ghost/preview с радиальным progress-индикатором задержки, если `total_spawn_preview_delay >= 0.25`.
- Радиальный индикатор расположен над ghost и диаметром не больше ширины персонажа.
- Ghost/preview появляется только после события rewind и скрытия текущей итерации, а не во время обычного бега по уровню.
- При `total_spawn_preview_delay < 0.25` показывается короткий spawn flash без countdown.
- Countdown не дублируется в основном HUD.
- При fail-state во время задержки ghost/countdown скрываются сразу.
- Задержка предотвращает стартовую блокировку прошлых клонов без ощущения лага управления.

### 17.1 MVP Implementation Snapshot

- Runtime-реализация добавлена в `TimeRewindController`.
- Реализовано:
  - world-space ghost/preview в точке spawn при `total_spawn_preview_delay >= delayed_spawn_preview_threshold_seconds`;
  - радиальный progress-индикатор без текста вокруг ghost/preview;
  - радиальный индикатор расположен над ghost, дефолтный радиус `0.32`, runtime clamp по ширине персонажа;
  - скрытие текущей итерации сразу при старте rewind;
  - короткий spawn flash при почти нулевой задержке и при обычном появлении;
  - скрытие preview при fail-state во время задержки;
  - отсутствие числового countdown в основном HUD;
  - serialized config-поля для `clone_spawn_delay_seconds` и `delayed_spawn_preview_threshold_seconds`.
- Статус проверки:
  - `dotnet build UnityProject/UnityProject.sln` завершился без ошибок;
  - пользователь подтвердил, что текущая версия работает и стабильна;
  - Unity batchmode в текущей shell-сессии завершался без stdout/log artifact, поэтому будущие автоматические Play Mode проверки остаются отдельной задачей.

## 18. План Релиза

- Формат выката: локальное обновление `TimeRewindTestScene`, затем ручная проверка в Unity Editor.
- Feature flags: не нужны для MVP; параметры контролируются config/scene values.
- Rollback plan: временно скрыть preview и оставить существующую задержку, если визуальный слой мешает проверке core loop.

## 19. Пострелизный Анализ

- Когда оцениваем: после локальной проверки и следующего onboarding-прототипа.
- Как интерпретируем результат:
  - если задержка воспринимается как таймлайн, можно строить tutorial;
  - если воспринимается как лаг, нужен более явный ghost -> player transition;
  - если spawn-конфликты частые, нужно пересмотреть level-design guidelines.
