## 1. Vision

Клоны должны быть физической частью puzzle-комнаты, а не только призрачной записью маршрута. Игрок может вмешиваться в прошлую итерацию: перепрыгивать клона, вставать перед ним, блокировать его путь, сдвигать его с кнопки или не давать ему попасть в ловушку.

Ключевое правило MVP: сдвинутый playback-клон принимает новое физическое положение как результат вмешательства игрока. Это поддерживает причинно-следственную связь "игрок вмешался в прошлую попытку -> последствия изменились".

Важное ограничение MVP: playback-клоны не должны физически сбивать записи других playback-клонов. Они остаются интерактивными для текущего игрока, объектов уровня, hazard и exit, но не должны создавать новый физический drift друг для друга в более поздних итерациях.

Если активный игрок сдвинул старого playback-клона, это вмешательство сохраняется не через повторное столкновение двух playback-клонов в следующей итерации, а через resolved path измененного клона.

## 2. MVP Debug Modes

- `Recover to recording`
  - Клон следует абсолютной записанной позиции.
  - Если игрок сдвигает стоящего клона с плиты и отпускает его, клон быстро возвращается к записанной точке.
  - Плюс: запись прошлого ощущается точной и стабильной.
  - Минус: физическое вмешательство игрока может выглядеть как временная помеха, а не как изменение результата.

- `Preserve displacement`
  - Клон не исправляет себя обратно к абсолютной позиции.
  - Клон применяет записанные дельты движения относительно текущего физического положения.
  - Если в записи клон стоял на месте, после сдвига он остается там, куда его сдвинули.
  - Плюс: вмешательство игрока становится более читаемым puzzle-инструментом.
  - Минус: точность записи становится менее буквальной.

## 3. Current Implementation

- Дефолтный режим: `Preserve displacement`.
- Debug-переключатель находится в editor/development debug-панели, а не в основном runtime HUD.
- Переключение применяется к уже существующим playback-клонам и к клонам, которые будут созданы после следующей отмотки.
- Клон по-прежнему не должен толкать текущего игрока.
- Playback-клоны игнорируют физические столкновения друг с другом, чтобы одна старая запись не ломала другую старую запись.
- После вмешательства текущего игрока клон получает visual altered feedback.
- Если текущий игрок изменил playback-клона, его фактический путь сохраняется для следующей отмотки.

## 4. Acceptance Criteria

- В режиме `Recover to recording` сдвинутый стоящий клон возвращается к записанной позиции.
- В режиме `Preserve displacement` сдвинутый стоящий клон остается на новом месте, если его записанная дельта движения равна нулю.
- В обоих режимах текущий игрок сохраняет физический приоритет над playback-клоном.
- В обоих режимах клон не проталкивает текущего игрока.
- Playback-клон не застревает на другом playback-клоне при повторном воспроизведении сценария, где в оригинальной записи столкновения не было.
- Playback-клон, который был сдвинут текущим игроком в прошлой итерации, воспроизводит измененный resolved path в следующей итерации.
- Переключение режима видно только в editor/development debug-панели и не требует пересборки сцены.
- В основном HUD публичной playable-сборки debug-переключатель не показывается.
